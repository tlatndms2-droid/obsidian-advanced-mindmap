# 02 — 데이터·상태·Vault 안전

| 데이터 | 성격 | 유지·변경 규칙 |
|---|---|---|
| `.canvas` 카드/위치/크기/연결선/색상 | Vault 원본 | 명시적 카드 작업에만 변경, 플러그인 비활성화·제거 시 보존 |
| 카드 Waypoint | 플러그인 참조 데이터 | Canvas별 등록, 카드 현재 위치 추적, 대상 삭제 시 해제, Undo 복원 |
| 카메라 Waypoint | 플러그인 화면 상태 데이터 | Canvas별 위치·Zoom 저장, 호출 시 복원 |
| Waypoint 이름 | 플러그인 데이터 | 등록 시 자동 생성, 직접 수정 가능, 덮어쓰기 시 새 이름 생성 |
| 사용자 색상 팔레트 | 플러그인 공유 데이터 | 모든 Canvas 공유, 카드에 적용된 실제 색상과 별개 |
| 설정값 | 플러그인 설정 | 재실행·비활성화 후 복원, 설정 백업 대상 |
| Undo/Redo | 임시 세션 상태 | Canvas별 독립, 재실행 시 초기화, 설정 백업에서 제외 |
| 팝업 크기 | UI 설정 상태 | 마지막 크기 저장·복원 |

## 수명주기
- Waypoint 등록/덮어쓰기/해제/이름 수정은 저장되고 Undo/Redo 지원.
- 카드 삭제와 해당 Waypoint 해제는 연결된 복원 작업으로 취급.
- Canvas 복제 시 Waypoint 번호·종류·이름·카메라 구도와 카드 참조가 복사본에 맞게 복제되어야 함.
- Canvas rename/move 후에도 기존 Waypoint를 찾을 수 있어야 함.
- 플러그인 제거 후 재설치에도 Waypoint·팔레트·설정 복원 요구. **Obsidian의 실제 제거 동작 및 보존 경로 검증 전에는 보장하지 말 것**.
- 색상 팔레트에서 사용자 색상을 삭제해도 원본 Canvas 카드 색상은 삭제하지 않음.
- 설정 백업에는 설정값만 포함. 백업 복원 시 Waypoint·팔레트·원본 데이터는 절대 변경하지 않음.

## 원자성/안전 기준
1. 카드 생성과 연쇄 밀어내기는 하나의 논리 작업으로 취급. 중간 실패 시 부분 이동 상태가 남지 않아야 함.
2. 위치 교환은 양쪽 카드 위치를 함께 복원할 수 있어야 함.
3. 다중 카드 색상 변경은 카드별 원래 색상을 정확히 기억하고 한 번에 복원.
4. 설정 복원은 전체 유효성 확인 후 적용. 실패 시 이전 설정을 온전히 보존.
5. 원본 Canvas/Markdown을 설정 백업·복원 과정에서 덮어쓰거나 삭제하지 않음.
6. 외부에서 Canvas 파일을 복제/이름 변경/이동한 경우 Waypoint 추적 가능 범위 및 한계는 공식 API/실제 테스트로 검증.

## 아직 확정되지 않은 사항
- 플러그인 제거 시 보존을 실현할 구체 경로·파일 형식은 Codex 검증/설계.
- 공식 Canvas API의 실제 접근 가능 범위와 Undo 통합 가능성은 Codex 검증.
- 사용자가 외부 파일 관리자로 복사한 Canvas까지 자동 Waypoint 복제 가능한지는 별도 검증. 사용자에게 이미 확정된 것처럼 보장 금지.
