# Canvas Mindmap 0.5.18 Sandbox 기능·성능 검증

검사일: 2026-10-21. 대상: Obsidian 1.14.4 / Windows / i7-13620H / RAM 31.7 GiB. 격리된 Canvas-Mindmap-Sandbox에서 실제 키 입력, 메뉴 클릭, 데이터 및 화면 확인을 수행했다. 제품 코드와 릴리즈는 변경하지 않았다.

## 판정

**전체 통과 아님.** 주요 기능은 통과했으나 빠른 생성→Undo→Redo에서 카드가 복원되지 않는 오류가 재현됐다. 파일 반복 전환 시 메모리 및 화면 요소 누적도 확인되어 원인 조사가 필요하다.

### 재현된 기능 오류

- 연결 생성(Ctrl+방향키) → 짧은 간격으로 Ctrl+Z → Ctrl+Shift+Z를 누르면 새 카드가 돌아오지 않는다.
- 100ms 추가 대기 조건에서 반복 재현. 입력 도우미 자체에도 100ms 대기가 있으므로 정확히 100ms 간격의 입력이라고 해석하면 안 된다.
- Redo 후 1.5초를 기다려도 새 카드가 돌아오지 않는다. 700ms 추가 대기 조건에서는 통과했다.
- 한 가지 오류를 여러 번 재현한 것이며 서로 다른 오류 세 개가 아니다. 원인과 수정은 이번 검증에서 확정하지 않았다.
- 증거: artifacts/full-0518/redo-100.json, redo-700.json, redo-settled-state.json.

### 파일 전환 누적

500개 카드 Canvas 두 파일을 번갈아 20회씩 열고 메모리 회수 후 측정했다.

|조건|JS 메모리 변화|화면 요소 수 변화|이벤트 리스너 수 변화|
|---|---:|---:|---:|
|플러그인 OFF 20회|35.10→36.68 MiB|8,491→13,508|1,844→10,616|
|플러그인 ON 20회|38.12→43.76 MiB|15,898→90,698|15,217→56,827|
|ON 추가 20회|44.37→49.15 MiB|91,958→155,138|59,257→92,767|

플러그인 ON에서 증가량이 더 크고 추가 반복에서도 늘었다. 장시간 사용 성능에 영향을 줄 수 있는 누적 현상이다. 앱 기본 캐시와 플러그인 보존 참조의 정확한 비중, 장시간 증가 상한은 아직 판정하지 않았다. JS 메모리는 Obsidian 전체 프로세스 메모리가 아니다. 증거: memory-control.json.

## 성능

각 동작 5회, 입력 전부터 두 번의 화면 갱신까지 측정한 중앙값. 자동화 통신 지연을 포함한다. 같은 PC의 다른 앱 부하 영향도 있으며 사용자 PC 전체 성능을 보장하지 않는다.

|카드 수|Alt 탐색|생성|정렬|JS 메모리|
|---:|---:|---:|---:|---:|
|100|54.02ms|51.33ms|43.48ms|25.87MiB|
|500|44.15ms|71.12ms|58.1ms|32.05MiB|
|1000|53.52ms|114.88ms|78.66ms|50.65MiB|

위 정렬은 연쇄 연결 배치에서 선택 카드 주변 정렬이다. 한 카드에 500개를 직접 연결한 별도 정렬은 **606.9ms**였다. 1,000카드 생성·Undo 등이 섞인 측정 구간의 최대 프레임 간격은 **153ms**, 50ms 초과 프레임은 1,927개 중 12개였다. 작업이 무거울 때 멈칫할 여지가 있다.

대기 중 렌더러 작업시간 비율은 100/500/1,000카드에서 4.84/9.71/8.39%였다. 1.5초 구간의 메인 렌더러 측정이며 PC 전체 CPU 사용률이 아니다. 팝업 20회 열고 닫기 후 JS 메모리 증가는 약 0.024MiB였다. 실측 성능 데이터와 검사 수행 성공을 '성능 무조건 통과'로 해석하지 않는다.

## 검사 범위의 한계 및 미수행

- 설정 백업/복원은 화면 버튼, 확인/취소, 실제 파일 내용, 손상 파일, 저장 실패 시 부분 적용 방지를 확인했다. Windows 파일 선택창 경로 반환은 시험용으로 지정했으며 네이티브 저장창 직접 조작은 미검사다.
- 파일 넣기는 빈 텍스트 카드에서 Markdown·Canvas·이미지·PDF·영상·음악을 각각 선택해 넣고 Undo했다. 모든 기존 파일 종류 간 교체 조합은 전수 검사하지 않았다.
- Canvas 복제와 내부/외부 이름 변경을 검사했다. 모든 폴더 이동·동기화 프로그램 조합은 미검사다.
- 기본 라이트/다크 800×650에서 색상 팔레트 위치를 검사했다. 모든 메뉴·서브메뉴·사용자 테마·다른 플러그인과의 충돌은 전수 검사하지 않았다. 좁은 화면 native 메뉴 캡처는 메뉴가 없어서 그 캡처로 검증하지 않았다. 재시작 후 일반 화면 native 메뉴는 실제로 다시 확인했다.
- 네 방향 생성 후 새 카드 ID 선택은 보완 검사(final-extra)로 재확인했다.
- 재시작 시험의 첫 시도는 시험 코드가 숫자열 1을 사용한 오류였다. 실제 기능의 숫자패드 1로 시험 코드를 고치고 등록→앱 종료→재시작→호출을 다시 수행해 통과했다. 제품 버그로 집계하지 않았다.
- 재시작 후 버전 0.5.18, 설정 전체, 카드와 Waypoint 데이터 일치 및 단축키 작동을 확인했다.
- 삭제·재설치 데이터 보존과 BRAT 설치/업데이트는 기존 제외 범위에 따라 미수행이다. 다른 Obsidian 버전, 수시간 연속 사용, 모든 미디어 코덱·네트워크 장애는 미검사다.
- 코드 검사와 실행 기록의 성공만으로 위 미수행 범위를 통과 처리하지 않았다.

## 남겨 둔 상태

Sandbox는 열어 두었고 검사 Canvas와 증거를 보관했다. 시험용 설정 변경은 기존 설정값으로 되돌린 뒤 저장했으며, 최종 화면은 빠른 Undo/Redo 오류를 재현한 Canvas다. 기존 사용자 작업 Vault에는 접근·변경하지 않았다. 검사 전 Sandbox 자료 백업은 artifacts/full-0518/backup.json 및 backup-* 파일에 있다.

다음 수정 우선순위는 빠른 Undo/Redo 복구, 파일 전환 시 누적 원인 제거, 다수 직접 연결 정렬의 지연 개선이다. 수정 작업은 이번 검증 범위에 포함하지 않았다.
