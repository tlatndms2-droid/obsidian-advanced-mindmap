# 0.5.19 수정 및 Sandbox 재검증 — 미배포

2026-10-21. Obsidian 1.14.4, 동일 Windows Sandbox와 PC에서 이전 오류의 재현 절차를 반복했다. GitHub push/Release/BRAT는 실행하지 않았다.

## 변경

- 빠른 생성 뒤 Undo/Redo: 이미 확정한 생성 결과를 지연 저장이 다시 기록하지 않도록 하고, Undo/Redo 적용 전후 대기 중인 기록을 취소한다. 카드·연결·선택 복원을 유지한다.
- 파일 전환 누적: 정리용 함수가 삭제된 Canvas/카드/iframe/document를 강하게 붙들지 않도록 변경했다. 재사용되는 Canvas 입력 영역의 기존 키 처리도 새 Canvas 처리로 교체하여 중첩하지 않는다. 살아 있는 대상은 플러그인 해제 때 기존 처리로 복원한다.
- 정렬: 기존 배치 계산 결과를 유지하면서 연결 부착면을 한 번 수집하고, 변경된 카드 좌표만 이동한다. 전체 카드 내용·파일 플레이어·연결을 다시 가져오는 경로를 제거했다. 카드 크기, 연결 방향/부착면, 먼 카드 보존 규칙은 유지한다.

## 결과

|기존 동작|생성·Tab·크기·연결·교환·색상·Waypoint·미디어·편집 관련 재검사 통과|
|재시작|0.5.19 로드, 설정·Canvas·Waypoint 데이터 일치, 메뉴/단축키 통과|
|코드|타입 검사, 10개 테스트 묶음, 빌드 통과|
|설치 파일|main.js·manifest.json·styles.css 로컬 빌드와 Sandbox SHA256 일치|

정렬 시간은 입력부터 두 번의 화면 갱신까지이며 자동화 통신 시간을 포함한다. 이전 단일 측정과 이번 5회 측정이므로 정밀 벤치마크 배수로 해석하지 않는다. 메모리는 전체 PC/Obsidian 프로세스 메모리가 아닌 JS 메모리다. 수시간 사용의 모든 누수를 증명한 것은 아니며, 기존에 재현된 반복 전환 누적은 이번 조건에서 사라졌다.

증거: `artifacts/fix-0519/`의 core.json, panels-redo.json, media.json, extra.json, memory-control.json, targets.json, restart.json, installed-hashes.json 및 화면 캡처. core.json은 버전 변경 전 동일 핵심 수정 코드의 검사이며 최종 0.5.19에서는 재시작 및 targets 검사를 다시 수행했다. iframe/document 정리 보완 뒤 YouTube·편집 관련 검사를 추가 수행했다.

## 사용자 확인

- 카드 선택 → Ctrl+방향키 생성 → 바로 Ctrl+Z → Ctrl+Shift+Z: 새 카드와 연결이 다시 나오고 새 카드가 선택되어야 한다.
- 여러 Canvas를 반복해서 전환하고 Ctrl+Shift+A/S, 색상 메뉴 방향키를 사용: 키 입력이 중복 실행되거나 점점 느려지지 않아야 한다.
- 연결된 기준 카드 → Ctrl+Shift+L: 기존 규칙으로 정렬되고 연결 부착면은 그대로여야 한다. Ctrl+Z는 원래 배치, Ctrl+Shift+Z는 정렬 배치를 복원해야 한다.

Sandbox는 `전체검증-수정검증완료` Canvas로 열어 두었다. 기존 사용자 Vault는 변경하지 않았다. 공개 배포 버전은 0.5.18로 유지하며 0.5.19는 로컬/Sandbox 전용이다.
